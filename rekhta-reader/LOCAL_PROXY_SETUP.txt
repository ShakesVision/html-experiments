========================================
LOCAL REVERSE PROXY SETUP FOR WINDOWS
========================================

Since tools.shakeeb.in is blocked from accessing ebooksapi.rekhta.org,
you need to run a local reverse proxy on your Windows machine.

QUICK START (2 steps):
1. Extract proxy.zip in this folder
2. Run: start-proxy.bat

That's it! Your local proxy will run on http://localhost:8888

USING WITH THE WEBAPP:
1. Open the Rekhta Reader in your browser
2. In the "Proxy prefix" field, enter:
   http://localhost:8888/?url={url}
3. Load a book URL as usual

HOW IT WORKS:
- The proxy forwards API requests from your browser to Rekhta's servers
- This bypasses the 403 CORS block on tools.shakeeb.in
- Your requests appear to come from localhost, not the blocked domain

TROUBLESHOOTING:
- If port 8888 is in use, edit start-proxy.bat to use a different port
- Make sure the proxy keeps running while using the reader
- If it stops, just run start-proxy.bat again

The root issue: Caddy cannot use a query-parameter value as a dynamic upstream — it requires a static upstream host known at config time. The ?url={encoded-url} format only works in a scripted proxy (Node.js, Python). The fix is to switch to a path-based format (http://localhost:8888/{hostpath}) that Caddy CAN route statically, and update both the Node.js proxy and the webapp to support it — while keeping backward compat with the old ?url={url} format.
